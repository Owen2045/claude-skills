# Jira 專案紀錄

把這個專案做過的事整理成兩份給 Jira 用的內容：多張 **sub-task**，加上一份**主 task 短版**。使用者會把標題複製到 Jira 開 sub-task，再把內文貼上。

## 資料來源

1. 本次對話的內容：做了什麼、結果、數字、決定、還沒做的部分。
2. 工作目錄根目錄的 `${CLAUDE_PROJECT_DIR}/jira-project.md`（上次的紀錄，存在才讀）。合併時，上次的項目保留，有新進度就更新該項，有新的功能塊就新增一張 sub-task。

只寫對話或舊紀錄裡有依據的事實。不確定的數字或狀態，放進「待確認」，不要猜。

## Sub-task 寫法

一張 sub-task 對應一塊功能或一份交付物。

**標題**：短名詞片語。需要時在括號標出階段或範圍。
- `登入安全`、`系統 log`、`介面調整`
- `資料表基礎（第 2 階段）`、`資料匯入 DB（第一批，本機）`

**內文**：一行一件事實，寫結果，不寫過程。
- 具體數字與規格：`6 碼，10 分鐘內有效`、`第一批匯入 3,568 筆`、`後端自動化測試共 39 項`
- 做到什麼程度：`已實測可以登入`、`兩輪驗證都通過`
- 範圍限制與還沒做的：`目前只套用在本機 DB`
- 過程中發現的重要事實：`發現某月料號整批改版，舊資料會歸到新料號`
- 前後對比：`原本約 290 列要逐列確認，現在減到 30 題必答`
- 有子項目時用「名稱：內容」：`主檔：品項、廠商、館別`
- 進行中的項目以 `進行中：` 開頭，需要對方或使用者確認的以 `待確認：` 開頭
- 技術名詞只在讀者需要時保留（表名前綴、路徑、加密演算法），其餘寫成一般中文
- 不用 Markdown 粗體、不加項目符號以外的格式

## 主 task 短版寫法

分三段，沒有內容的段落省略：

```
已完成
第 1 階段 demo 已上線
登入加上 Email 驗證碼，系統 log 也已完成
介面已調整：修正頁籤切換、統一圖表配色和表格對齊

進行中
<功能> 開發中，預計 <下一步>

待確認
<要誰確認什麼>
```

- 每張 sub-task 濃縮成一行，相關的可以併成一行。
- 「已完成」用「已…」句型；「進行中」寫正在做什麼；「待確認」寫要誰確認什麼。
- 不放數字和規格，細節留在 sub-task。

## 輸出格式

每張 sub-task 的標題和內文**各自放在一個 code block**，方便分開複製：

````
### Sub-task 1
標題：
```
登入安全
```
內文：
```
LINE 登入後要再輸入 Email 驗證碼：6 碼，10 分鐘內有效，有防暴力破解和寄信頻率限制
已實測可以登入
```
````

所有 sub-task 之後，主 task 短版整份放在一個 code block。

## 存檔

把同樣的內容（不含 code block 標記，用 `## <標題>` 分隔每張 sub-task，最後是 `## 主 task`）寫入 `${CLAUDE_PROJECT_DIR}/jira-project.md`，整份覆寫。這是工作目錄的根目錄，不是 clone 下來的 git repo 裡面。回覆最後一行告訴使用者檔案路徑，以及這次新增或更新了哪幾張 sub-task。
