# Jira 時間軸紀錄

留下可以對帳的時間軸：誰在什麼時候給了什麼、向對方要了什麼、做法為什麼改。紀錄跨很多次對話累積，存在檔案裡。

紀錄檔：`${CLAUDE_PROJECT_DIR}/jira-log.md`。這是工作目錄的根目錄，不是 clone 下來的 git repo 裡面，所以不會被 git 追蹤。

## 什麼時候寫

- 使用者輸入 `/owen-jira-timeline`：
  - `jira-log.md` 不存在：建立檔案，第一行寫 `# <專案名> 時間軸`，專案名用工作目錄資料夾名，再問使用者要不要補記之前的事件。
  - 已存在：把整份紀錄（不含標題行）放在一個 code block 輸出，方便貼到 Jira。
- `jira-log.md` 已存在時，自動新增一行，不用等使用者叫：
  - 你讀了使用者說是需求方、客戶或對方提供的檔案
  - 使用者說收到資料、向對方要了什麼、開始做、做完、改做法、卡住
- `jira-log.md` 不存在時，不要自動建立。這個專案沒有開時間軸模式。

每次新增後，在回覆最後用一行告訴使用者加了什麼，例如：`已記錄到 jira-log.md：2026/09/21 16:11 收到耗材&退貨文件，開始整理`。寫錯時照使用者的話修改那一行。

## 時間

- 預設用現在時間。執行指令取得，不要猜：Bash 用 `date "+%Y/%m/%d %H:%M"`，PowerShell 用 `Get-Date -Format "yyyy/MM/dd HH:mm"`。
- 使用者有指定時間（例如「這是 9/15 收到的」）就照使用者的，沒說幾點就只寫日期。
- 格式：`YYYY/MM/DD HH:mm`，月日補零。只有日期時寫 `YYYY/MM/DD`。

## 一行的寫法

`<時間> <事件>`，一行一件事，依時間順序附加在檔案最後。同一時間有多件事就寫多行。

| 類型 | 寫法 | 例子 |
|---|---|---|
| 收到資料 | 收到／需求方已提供 + 檔名原文 + 接著做什麼 | `需求方已提供文件 - 202607獎金.xlsx，同步開始進行公式整理` |
| 向對方要資料 | 跟需求方要 + 要什麼 | `跟需求方要 A、B 產品的相關文件` |
| 開始 | 開始 + 做什麼 | `開始實做獎金設定、凍結等功能` |
| 完成 | …已完成 + 後續 | `耗材&退貨已開發完成，後續開發封存、公式 table 等功能` |
| 改做法 | 因 + 原因，所以 + 新做法 + 資料來源 | `因安全性考量，無權限連上 ERP DB，所以改用讀取同步資料庫的方式實作` |
| 未解決 | 剩餘 + 什麼 + 卡在哪 | `剩餘保養品需要討論後續作法（同步資料庫沒有保養品資料）` |

- 檔名照原文寫，含副檔名。
- 提到對方時用「需求方」，使用者有給名字就用名字。
- 只寫事實，不寫情緒或評價。延遲的事實會從日期差看出來，不用另外寫。
